# Phantom OTC

Telegram-бот гаранта для сделок в **TON** и **USDT** (сеть TON).  
Стек: Python 3.11–3.13, aiogram 3, SQLite, tonutils (Wallet V4R2), pyrofork для NFT-банка.

Покупатель заранее кладёт монеты на баланс бота. Когда сделка стартует, сумма **замораживается** и её нельзя вывести. После «Товар получен» продавец получает деньги минус комиссия. Если что-то не так — спор, решение за админом.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp config.ini.example config.ini
```

Нужен пакет **pyrofork**, не `pyrogram`. Если стоит обычный pyrogram:

```bash
pip uninstall -y pyrogram
pip install -U "pyrofork>=2.3.45"
```

В `config.ini` укажите `[bot] token` и `admin_ids`. Затем:

```bash
python main.py
```

Все кнопки инлайн. `/admin` доступен только ID из `admin_ids`. В главном меню у админа есть пункт «Админка».

## Как устроены деньги

Только **TON** и **USDT** (jetton в сети TON). Рублей, карт и Qiwi нет.

| Поле | Смысл |
|---|---|
| `balance` | всего USDT |
| `balance_ton` | всего TON |
| `frozen_usdt` / `frozen_ton` | заморожено в открытых сделках |
| доступно | всего − заморожено |

- Пополнение: постоянный memo `G{telegram_id}`. Перевод TON или USDT на адрес эскроу с этим комментарием зачисляется сам (бот смотрит сеть каждые ~25 сек). «Проверить» — сразу. Заявок и ручного подтверждения нет.
- Вывод: сумма сразу списывается с доступного баланса, админ подтверждает заявку — бот сам отправляет TON или USDT с кошелька эскроу. Пока заявка `pending` или `sending`, новую создать нельзя.
- Комиссия `[bot] commission_percent` берётся с продавца при закрытии сделки.

Адрес эскроу и seed — секция `[ton]`. USDT master по умолчанию: `EQCxE6mUtQJKFnGfaROTKOt1lZbDiiX1kCixRv7Nw2Id_sDs`.

## Сделки

Создаёт только **продавец**: напрямую по username или объявлением в канал (`[bot] deals_channel`, бот должен уметь писать в канал).

1. Продавец указывает категорию, валюту, цену, описание. Для аккаунтов — секрет (логин/пароль), его видят только стороны и админ.
2. Покупатель не может взять сделку, если на балансе меньше цены.
3. В момент «принять / взять» сумма замораживается.
4. NFT-подарок бот отправляет **после** заморозки.
5. Покупатель жмёт «Товар получен» → продавец получает выплату, сделка закрывается.
6. В открытой сделке и в споре стороны шлют **фото** кнопкой «Фото».
7. Отмена открытой сделки **взаимная**: одна сторона запрашивает, вторая соглашается. После отправки NFT отмена только через спор.
8. Спор: причина, фото, переписка, вердикт админа покупателю или продавцу.

Категории: аккаунты (Roblox, Steam, Epic, Discord, Telegram, соцсети, игры), NFT-подарки Telegram, товар, другое.

## NFT-банк

Отдельный **юзер-аккаунт** Telegram (не токен бота). На него кидают подарки, с него бот передаёт их покупателю.

Сессия: `[bank] session`. Первый вход по телефону — запустите `python main.py` в консоли: бот спросит `api_id` / `api_hash` (https://my.telegram.org), телефон и код.

Либо импорт готовой Pyrogram/pyrofork-сессии:

```bash
python scripts/login_bank.py --from путь/к/config.json
python scripts/login_bank.py --from путь/к/файл.session
```

Telethon-сессия не подойдёт. Без `[bank] session` бот работает, инвентарь NFT сам не наполняется.

Передача уникального подарка списывает Stars (обычно 25★). Если Stars мало, бот докупает пакет через Fragment с **отдельного** кошелька `[fragment]` (не путать с `[ton] mnemonic`).

```
[fragment]
mnemonic =
api_key =
cookies =
wallet = V4R2
stars = 100
provider = toncenter
```

Получатель пакета — `[bank] username`. Без mnemonic автопокупка выключена.

## Админка

`/admin` или кнопка в меню:

- статистика, споры, история пополнений, заявки на вывод;
- баны (в том числе по `@username`);
- FAQ, картинки экранов, баланс пользователя;
- кошельки, сессии банка/Fragment, список админов;
- названия, цвет и премиум-эмодзи кнопок.

Картинки: админка → «Картинки меню» или файлы в `assets/` (`assets/README.txt`). Фото из бота важнее файла на диске.

## Конфиг

Смотрите `config.ini.example`. Сам `config.ini` в git не хранится.

База: SQLite `data/garant.db`, создаётся при старте. Старые колонки подтягиваются миграцией.
